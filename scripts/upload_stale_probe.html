File input that React swaps out underneath you

Reproduces the Westbay/Rippling failure from 2026-09-11: our CDP call reports success, no error, and the page still holds files=[(none)].

The mechanism modelled here: the form re-renders and REPLACES the <input type=file> with a fresh, identical node. Any backendNodeId captured before that moment now refers to a detached element. DOM.setFileInputFiles against it succeeds - it really did set files on a node - but the live input the form reads is untouched. A verification that resolves the SAME stale id would also pass, which is why the check must re-find the input from the live document.
